# Attaching evidence

Agents attach files to an item as proof of their work: a GIF reproducing a bug, a before and after screenshot, a video, a diff, a log or test output.

```sh
otea attach BUGS-1 shots/before.png --role before --caption "Blank page after save" --as claude
otea attach BUGS-1 shots/after.png --role after --as claude
otea attach BUGS-1 test-output.log --caption "12 tests pass" --as claude
otea show BUGS-1                           # lists the evidence above the timeline
```

- `otea attach <id> <file>` copies the file into `evidence/` in the project's data folder (`.otea/evidence/` for a local project), named by its sha256, so attaching the same content twice stores it once; nothing lands in the repo's tracked files. It prints the entry: id, role, kind, file name, size and caption (`--json`: also `contentType`, `sha256`, `createdAt`, `actor` and `channel`). A relative path is resolved against the current directory.
- `--role` is `before`, `after` or `single` (the default). There is no pair id: a viewer pairs the latest `before` with the latest `after`.
- When the item's type places evidence modules in its layout (see the product definition, §9), the file goes to one of them, and the entry records which (`module`, its id):
  - A file no module of the type accepts is refused with exit 15 (`evidence_not_accepted`); the message lists what each module takes.
  - When several modules accept it, `--module <id>` says which, otherwise exit 2 (`module_required`). A module's id is its `id:` in the layout, or its module kind (`images`, `log`) when it declares none; ids are unique within a type. An unknown id fails with exit 3 (`not_found`).
  - A `compare` module takes only `--role before` or `--role after`; every other module takes single files. A role that does not fit fails with exit 2 (`invalid_role`).
  - A type that places no evidence module takes any file in any role, as before. Evidence attached before modules existed (or to a module a board edit removed) belongs to the first module that accepts it. On a board, a file the person adds (when creating the item or later from its page, `POST /api/items/:id/evidence`) goes to a part the creation form asks for when one takes it, else it stays with the item outside the parts: the parts the steps hand are the agents' deliverables, and a person's file never fills one unless the person names it.
- `otea show` groups the evidence by module, in layout order, marks required ones and says `nothing yet` for an empty one; files no module draws come last as `other files`. The MCP `attach` tool takes the same `module` and `role`.
- The kind comes from the extension: `gif`, `png`, `jpg`, `jpeg` and `webp` are images; `mp4`, `webm` and `mov` videos; `diff` and `patch` diffs; `log` and `txt` logs; anything else, SVG included (it can carry scripts), is a plain file.
- A unified diff saved as `.txt` or `.log` is a log, so attached without `--module` it goes to a part that takes logs. When the item also has a part that takes diffs, `attach` says so and gives the commands that put it there (save it as `.diff`, attach that with `--module`, then `detach` the first); `--json` carries `diffPart` and `diffNote`. When several log parts fit, the refusal that asks for `--module` names the diff part too.
- Evidence is append-only, like the event log, and each attachment adds an `evidence_added` event to the timeline. Attaching the same file again (same content, module, role and caption) before the item moves adds nothing: `otea attach` prints the entry it already has and says so (`--json`: the entry with `"duplicate": true`). Once the item moves, as in a new round, the same file is a new entry. A file attached by mistake comes off with `otea detach <id> <n>` (`#3` or `3`, as `show` numbers it), only by whoever attached it and only before the item moves on; a file a note of the person or the proof of a point rests on stays. The entry is kept and an `evidence_detached` event records it. It follows the rules of `otea update`: an item another agent holds refuses it (exit 12, `lease_held`) and so does a closed item (exit 4, `item_closed`). A missing file fails with exit 3 (`file_not_found`) and one over 50 MB with exit 14 (`evidence_too_large`).
- `otea show --json` and `GET /api/items/:id` list the entries under `evidence`. `GET /api/evidence/:id/file` serves the file to a signed-in browser only (401 otherwise), with `X-Content-Type-Options: nosniff` and `Content-Security-Policy: sandbox`: images and videos inline with their type, diffs and logs as `text/plain`, anything else as a download, so no attached file runs in the UI's origin. It serves byte ranges (`Range: bytes=…`, 206), so videos seek.
- The item detail draws each evidence module where the layout places it: `images` as one image (`single`), a gallery with thumbnails (`gallery`, left and right arrows step through it; on a reviewed item each picture says its round, and **Compare with round n** opens the picture shown beside its version in the round before, paired by name as the phone pairs them, in the before/after compare) or a before/after slider with a draggable divider and a side-by-side mode (`compare`; the divider is a keyboard slider); `recording` in the browser's player (`player`, nothing autoplays) or as a strip of eight frames read from the video (`frames`, falling back to the player when the browser cannot read frames); `diff` as files, hunks and numbered lines; `log` numbered, with a wrap toggle, keeping only its start and end until "show all" when longer than 160 lines. An empty module says what agents attach, and a required one is drawn dashed. A browser that is not signed in lists file names only.
